# ตัวบันทึกภาพกล้อง

เว็บแสดงว่ากล้องเห็นอะไร**ตอนนี้** ตัวนี้เก็บว่ากล้องเคยเห็นอะไร — เก็บภาพจากทุกกล้อง
เป็นระยะ พอหมดวันก็ต่อเป็นวิดีโอหนึ่งไฟล์ แล้วลบทิ้งเมื่อเกินกรอบที่ตั้งไว้

```sh
npm run record          # เก็บไปเรื่อย ๆ
npm run record:once     # เก็บรอบเดียวแล้วจบ (ไว้ทดสอบ)
```

| ตัวเลือก | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `--out` | `D:/CCTV` (หรือ `CCTV_DIR`) | ที่เก็บ |
| `--interval` | `600` | วินาทีระหว่างรอบ (10 นาที) |
| `--keep-days` | `5` | เก็บกี่วัน |
| `--workers` | `8` | ดึงพร้อมกันกี่กล้อง |
| `--video-fps` | `10` | อัตราเล่นของวิดีโอที่ต่อแล้ว |

## โครงสร้างที่ได้

```
D:/CCTV/
  ITICM_BMAMI0074/
    2026-09-09/         เฟรมของวันที่กำลังเก็บ
      14-20-49.jpg
    2026-09-09.mp4      วันที่กำลังเก็บ ต่อใหม่ทุกรอบ เฟรมยังอยู่
    2026-09-08.mp4      วันที่จบแล้ว ต่อครั้งสุดท้าย เฟรมถูกลบ
    2026-09-08.csv      หนึ่งบรรทัดต่อเฟรม
```

วิดีโอของวันปัจจุบันถูกต่อใหม่ทุกรอบ ไม่ใช่รอจนหมดวัน การ์ดบนเว็บจึงเห็นภาพเคลื่อนไหว
ตั้งแต่มีไม่กี่เฟรม แทนที่จะเป็นภาพนิ่งจนถึงเที่ยงคืน ต่อใหม่ครั้งหนึ่งใช้ 0.3 วินาที
ต่อกล้อง (วัดที่ 27 เฟรม) และวันหนึ่งมีมากสุด 144 เฟรม

ระหว่างต่อจะเขียนเป็น `<วันที่>.writing.mp4` ก่อนแล้วค่อยย้ายทับ เพราะเว็บเซิร์ฟเวอร์
อาจกำลังส่งไฟล์เดิมให้ใครอยู่ — และชื่อชั่วคราวต้องลงท้าย `.mp4` ด้วย เพราะ OpenCV
เลือก container จากนามสกุล ถ้าตั้งเป็น `.part` มันจะเปิด writer ไม่ได้เลย

## เรื่องระยะห่างระหว่างรอบ

ทุกเฟรมต้องเปิดการเชื่อมต่อ HLS ใหม่ — playlist, segment แรก, แล้วค่อยได้เฟรม
วัดรอบเก็บครบทุกกล้องได้ **77 วินาทีที่ 8 workers และ 73 วินาทีที่ 16 workers**
เพิ่ม thread ไม่ช่วยเพราะคอขวดคือการต่อเชื่อม ไม่ใช่จำนวน thread และพอใส่การตรวจจับ
เข้าไปด้วย รอบหนึ่งกินเวลาจริง **108–131 วินาที**

**นั่นคือพื้น ไม่ใช่ค่าที่ตั้ง** อะไรที่ต่ำกว่าราวสองนาทีจะเริ่มรอบใหม่ก่อนรอบเก่าจบ
ค่าเริ่มต้นตอนนี้คือ 10 นาที ซึ่งอยู่เหนือพื้นนั้นมาก

**เก็บทุก 10 วินาทีทำไม่ได้** จะได้ต้องเปิดสตรีมค้างไว้ 27 เส้นพร้อมกัน ซึ่งชนกับ
แบนด์วิดท์ที่วัดไว้ใน `public/js/app.js` — แต่ละสตรีมกิน 0.3–6.8 Mbps และแปดเส้น
ขนานกันแชร์กันได้แค่ 2.5 Mbps รวม

Longdo ระบายสีถนนใหม่ทุก 5 นาที การเก็บทุก 10 นาทีจึงอยู่ในระดับเดียวกับข้อมูลที่มัน
วางเทียบอยู่ ไม่ได้หยาบกว่ากันมาก

## 10 นาทีใช้ทำอะไรได้ ใช้ทำอะไรไม่ได้

**ไม่ได้:** ตามรอยรถทีละคัน รถวิ่งพ้นเฟรมไปนานมากแล้วระหว่างสองภาพ ตัวนี้จึงไม่ใช่
ตัวตรวจจับอีกตัว ถ้าต้องการนับรถแบบ tracking ให้ใช้ `detector/` ซึ่งทำงานที่ 7-8 fps
บนกล้องที่มีคนเปิดดูอยู่

**ได้:** ความหนาแน่นของแต่ละจุดตามช่วงเวลา ซึ่งเป็นสิ่งที่ `logger/` (เก็บสีถนนจาก
ไทล์ทุก 5 นาที) ต้องการเพื่อให้พยากรณ์ได้ — อันนั้นบอกว่าถนน*ดูแน่นแค่ไหน* อันนี้เก็บ
ภาพจริงไว้ให้ย้อนดูได้ว่าตอนนั้นเกิดอะไรขึ้น
