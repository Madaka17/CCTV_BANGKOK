# ตัวเก็บข้อมูลจราจรย้อนหลัง

## ทำไมต้องมี

Longdo เผยแพร่สภาพจราจรเป็น vector tile แต่ให้เฉพาะ**สภาพ ณ ตอนนี้** ไม่มีย้อนหลัง
ไม่มีพยากรณ์ การจะพยากรณ์ได้ต้องมีอดีตให้เรียนรู้ ตัวนี้จึงเก็บ tile ที่ครอบคลุม
กรุงเทพไว้เป็นระยะ

## ใช้งาน

```sh
npm run log:once      # เก็บหนึ่งครั้งแล้วจบ (ไว้ทดสอบ)
npm run log:traffic   # เก็บทุก 5 นาที ปล่อยหน้าต่างไว้
```

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `INTERVAL_MINUTES` | `5` | ระยะห่างระหว่างการเก็บ |
| `TRAFFIC_ZOOM` | `12` | zoom ของ tile (สูงสุดที่ Longdo มี) |
| `TRAFFIC_LOG_DIR` | `data/traffic-history` | ที่เก็บ |

## ขนาดข้อมูล

56 tiles ครอบคลุมกรุงเทพ บีบ gzip แล้วราว 227 KB ต่อครั้ง

| ความถี่ | ต่อวัน | ต่อเดือน |
|---|---|---|
| ทุก 5 นาที | 64 MB | 1.9 GB |
| ทุก 10 นาที | 32 MB | 0.9 GB |
| ทุก 15 นาที | 21 MB | 0.6 GB |

โฟลเดอร์นี้อยู่ใน `.gitignore` ไม่ถูก commit

## แปลงเป็นตาราง

```sh
python3 -m venv .venv
.venv/bin/pip install mapbox-vector-tile
.venv/bin/python logger/decode-traffic.py
```

ได้ `data/traffic-history.csv` หนึ่งแถวต่อหนึ่งเส้นถนนต่อหนึ่งครั้งที่เก็บ:

```csv
at,segment,lat,lng,forward,reverse
2026-09-08T06:26:32.460Z,41731c3ef482,13.963805,100.351889,0,
```

- `segment` — รหัสประจำเส้นถนน
- `forward` / `reverse` — ขาไป / ขากลับ: `0` คล่องตัว, `1` ชะลอตัว, `2` ติดขัด, ว่าง = ไม่มีข้อมูล

## เรื่อง `segment` ที่ต้องเข้าใจ

tile ของ Longdo **ไม่มี id ประจำเส้นถนน** (ทุก feature รายงาน id เป็น 0) แต่รูปทรง
ของถนนไม่ขยับ ตัวถอดจึงใช้ hash ของพิกัดเป็นตัวระบุแทน

ทดสอบแล้วใช้ได้จริง — เก็บสองรอบห่างกัน ได้ 22,111 เส้นเท่ากัน และรหัสตรงกัน 100%
นี่คือสิ่งที่ทำให้สร้าง time series รายถนนได้

ข้อควรระวัง: ถ้า Longdo แก้ไขรูปทรงถนนเส้นไหน รหัสของเส้นนั้นจะเปลี่ยน และจะดูเหมือน
ถนนเส้นเก่าหายไปแล้วมีเส้นใหม่โผล่มา — ตอนวิเคราะห์ควรทิ้งเส้นที่มีข้อมูลไม่ต่อเนื่อง
